# P0 压测基线报告

执行时间：2026/10/22 22:53:17 至 2026/10/22 23:03:09。

## 环境与口径

- Windows 本机 16 逻辑处理器，内存 15.3 GiB；Docker 分配 16 CPU、7.4 GiB 内存。
- 真实编译的单实例 API、独立 Worker；压测器与服务同机。MySQL 8、Redis 7、RabbitMQ 3.12 使用独立容器和端口。
- 测试 MySQL max_connections=400、InnoDB buffer pool=128 MiB，详见 compose.p0.yml；业务连接池未修改。
- 6,000 个压测账号、另一个作者账号、50,000 条视频。测试会话提前生成，鉴权和限流照常执行；不计入登录/密码校验性能。
- 25/100/300 并发闭环客户端；每组读取持续 20 秒。每组互动发送 2,000 次独立账号请求，是有限批次突发测试，不代表长期持续写入能力。
- 每轮按同一顺序执行，缓存会逐步预热；热点详情失效场景每秒删除一次测试热点缓存。数据时间戳间隔一秒，未覆盖相同时间戳的视频分页。
- 有效 RPS 仅计 HTTP 200 且响应校验通过的请求；延迟统计包含失败请求，在途请求完成时间计入窗口。未设置业务 SLA，不能据此声称生产容量或最大稳定并发。
- 落库延迟由压测期间及结束后每 250ms 轮询观察，包含观察间隔和查询时间；最终记录、计数、Redis 热度、通知另行核对。

共发出 3,293,555 次被统计请求，其中有效响应 3,227,624 次；预热及分页检查不包含在此计数中。重复点赞正确性场景单独解释。
